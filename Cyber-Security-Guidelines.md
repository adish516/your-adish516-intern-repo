# Cyber Security Reflection

## Common threats when working remotely

Working remotely means a lot of communication happens through emails,
messages and shared links. That makes it important to check what I’m
opening, especially if someone asks me to log in, download something
or share information unexpectedly.

Other risks include reused passwords, outdated software, lost devices
and accidentally sharing company information in the wrong place.
Even something like uploading a file to a public GitHub repository
could expose information if I haven’t checked what’s inside it.

## Keeping devices and accounts secure

I would keep my devices and apps updated, use different passwords for
each account and enable two-factor authentication wherever possible.
I would also install software from trusted sources and avoid giving
apps permissions they don’t need.

For company information, I would use the tools and storage locations
approved by the team. I wouldn’t paste private company or user data
into an AI tool without checking that it’s allowed.

## Why locking my computer matters

Being away for a few minutes is still enough time for someone to
access an unlocked device. If my work accounts are open, they could
see information or send messages using my account.

I’ll lock my laptop whenever I step away and set my laptop and phone
to lock automatically after a few minutes. Unlocking should require
a password, PIN or biometric login.

## Handling suspicious messages and links

If a message looks suspicious, I wouldn’t click the link or open
the attachment just to see what it is. I would check the sender’s
actual address and look out for unusual requests or pressure to
act quickly.

If it appears to come from a colleague, I would confirm with them
through a separate, trusted channel. For account alerts, I would
open the official app or website directly rather than use the link.

I would report suspicious work messages through the team’s agreed
channel instead of forwarding potentially harmful links around.

## Strong passwords and password managers

A strong password should be long, unique and difficult to guess.
Using the same password everywhere means one leaked password could
put several accounts at risk.

A password manager would help me generate and store different
passwords without needing to remember all of them. I would protect
the manager itself with a strong master password and 2FA.

I also learned during the GitHub setup that access tokens need to
be treated like passwords. They shouldn’t go into messages,
screenshots or public repositories.

## Why 2FA is important

2FA adds another check when signing in, so a stolen password alone
is usually not enough to access the account. I would enable it
wherever it’s available, especially for email, GitHub and work tools.

I wouldn’t share verification codes or approve login requests that
I didn’t initiate. I would also store recovery codes somewhere secure.

## My current habits and where I can improve

The GitHub setup made me more aware of how carefully I need to handle
access tokens. I want to carry that awareness into everyday work,
especially when sharing screenshots or uploading files.

Rather than assume all my accounts are secure, I need to check my
passwords, 2FA settings and automatic screen locks. The checklist
below records what I’ve actually reviewed.

## Making security a habit

I want security checks to become part of how I work. Before sending
a screenshot or uploading a file, I’ll check for passwords, tokens,
personal details and private company information.

I’ll also lock my screen whenever I leave my desk and pay attention
to update notifications rather than keep putting them off.

## What I would do if I suspected a breach

I would stop interacting with the suspicious message or website and
report the issue promptly to my supervisor or the designated security
contact. I would explain what happened, when it happened and whether
I clicked anything, downloaded a file or entered any information.

If an account might be compromised, I would use a trusted device and
the official website to change the password and revoke unfamiliar
sessions. If a token was exposed, I would revoke and replace it.

I would follow the team’s incident process and keep relevant details
or screenshots without including secrets. I wouldn’t hide a mistake
or wait until I was completely certain before reporting it.
